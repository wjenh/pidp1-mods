**Known constraints, carry forward:**
- Deleting or renaming files in this connected folder fails with "Operation not permitted," and `allow_cowork_file_delete` doesn't recognize this mount. `cp` works fine though (no delete needed), which is how phase 4's directory "renames" were actually done: copy to the new location, fix up the copy, build-verify, then queue the old location in `needsdelete.sh` for the user to remove by hand.
- The Write/Edit tools write directly to this mount and were NOT observed to serve stale reads to a subsequent bash command this session (unlike the historical gotcha recorded in `Claude/CLAUDE.md`). Still worth a quick sanity check after editing a file a build will read, in case this was session-specific rather than fixed.
- `sandbox-libs/bootstrap.sh` re-copies vendored headers (with a fresh mtime) every time it is sourced, which causes a false-positive rebuild if `make` runs in a separate bash-tool call from the previous build (env vars, and therefore the fresh-header illusion, don't persist across calls). To verify true no-op-rebuild behavior, chain `bootstrap.sh` and all the `make` invocations together in one bash call.
- `make clean` fails in this mount for the same delete-restriction reason as above; verify by building fresh into whatever `.o`/`.d`/binaries are already present rather than cleaning first.
- Verifying a build leaves `.o`/`.d`/binary artifacts behind; `.gitignore` covers `*.o`/`*.d` going forward but the already-generated files, plus any relocated-directory leftovers, still need `needsdelete.sh`. Everything from phases 3 and 4 is queued there now, not yet run by the user.
- `REFACTOR-CHANGES.txt` only gets DELETE/COPY entries for actual file moves/removals, not plain content edits (Makefile tweaks, doc path fixes) -- those go in the relevant nested `CLAUDE.md` instead, or just get made in place if there's no natural nested-doc home for the note.
